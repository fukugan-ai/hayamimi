# IP-2 の実走の記録

IP-2 は、`lat-dialog`（ja と en の交互の 30 発話）を 3 repeat、1 本のマイクから `hayamimi`、中継、訳の server を通して流し、記録が欠けないこと（合否）と、各発話が自分の言語で読まれたか（記録だけ）を見る受入である。
2026-10-23 に、設計 10.9 の IP-2 の command のとおり `pair` と `fast` の 2 本を流した。

## 行ごとの結果

| 行 | 結果 | 理由 |
|---|---|---|
| T-IP-02-015 `lat_dialog_has_thirty_utterances_and_twenty_nine_switches` | 通った | `test lat_dialog_has_thirty_utterances_and_twenty_nine_switches ... ok` |
| T-IP-02-001 `ip02_each_dialog_utterance_is_read_in_its_own_language` | 打てなかった | `Error: "2 llama-server processes are running"` |

要約行：`test result: FAILED. 1 passed; 1 failed; 0 ignored; 0 measured; 16 filtered out; finished in 0.03s`

T-IP-02-001 が打てなかった理由は、test の `find_llama` が、機械に居る `llama-server` がちょうど 1 つであることを要るからである。
この run では、共有の 18081 の `llama-server` に加えて、訳の server を 18084 で別に起こしていた。
共有の server を止める、`--own-pid` に渡すことは採らない手段なので、test を通すために数を 1 に合わせていない。
test は、`require_free_ports` で 8833、8835、8766 が空いていることを確かめた後にこの error を返し、`hayamimi` も中継も起こさなかった。
test が最初に書く `ip02.md` の 1 行目（`# IP-2 record`）は、この文書で置き換えた。

## 設計の合否の文を、手で打った run に当てた結果

設計 10.9 の IP-2 の合否の文（逐語）：

> `lat-dialog` の run が欠けなく 1 本記録される（`stream.machine.refused` なし）。欠けないとは、`ip02_pair.jsonl` が 90 行（repeat 1〜3 と発話 1〜30 が 1 回ずつ）で、同じ名前の `.events.jsonl`、`.summary.json`、`.machine.jsonl` が在り、`final` が 1 件以上在ることである。

test が打てなかったので、設計の command を手で打ち、文の各項を数えた。
次の表は、test の関数の出力ではなく、手で打った run の file への `wc`、`jq`、`grep -c` の数である。

| 項 | `pair` | `fast` |
|---|---|---|
| `ip02_<mode>.jsonl` の行数（期待 90） | 90 | 90 |
| repeat と発話の組の数（`jq -r '[.repeat,.utt]\|@tsv' \| sort -u \| wc -l`。期待 90） | 90 | 90 |
| `.events.jsonl`、`.summary.json`、`.machine.jsonl` | 3 つとも在る | 3 つとも在る |
| `stream.machine.refused`（`stream` の出力と `.machine.jsonl` への `grep -c`） | 0 と 0 | 0 と 0 |
| `final` の数 | 113 | 113 |

`grep -c` の対照として、同じ語を、machine の門が断った IP-5 の 1 回目の出力（cargo の親 process が居た run）に打つと 1 を返す。
`final` の数 113 は、`.jsonl` の各行の `finals` の和（`pair` 113、`fast` 113）と一致した。

この 5 項は `pair` と `fast` のどちらでも満たされた。
ただし、T-IP-02-001 という行は打てていない。

## 打った command

訳の server、`hayamimi`、中継、`stream` を、それぞれ `sudo -n nice -n -5 sudo -n -u <本人>` を前に付けて起こした（この機械の shell の nice が 5 なので、起こした process の nice は 0 になった）。

```
llama-server -m CAT-Translate-3.3b-Q8_0.gguf --host 127.0.0.1 --port 18084 -ngl 99 -c 16384
hayamimi --input ws --mode pair --source file --models <repo>/models --serve 8833
hayamimi-relay live --events http://127.0.0.1:8833/events --llm http://127.0.0.1:18084 --serve 8835
hayamimi-eval stream --wav testdata/lat-dialog.wav --repeat 3 --relay-port 8835 --own-pid <hayamimi> --own-pid <中継> --own-pid <訳の server> --own-llama-port 18084 --out ip02_pair.jsonl
```

続けて `hayamimi` と中継を止め、`--mode fast` で `hayamimi` と中継を起こし直し（pid は新しい物）、同じ形で `--out ip02_fast.jsonl` を取った。
その後、`ip02` の test binary（`native/target/release/deps/ip02-7450c79ac7f197c6 --ignored`）を `cargo` の親 process なしで直に起こした。
`cargo test` の形にしなかった理由は `ip05.md` にある。`stream` は `cargo` の process が居ると起動を断る。

## 記録だけの数

数え方は設計 10.9.2 である。
test の関数（`record_dialog_run`）が走らなかったので、同じ file を `jq` で数えた（式は run の dir の `count.jq`。repo に入れていない）。
母数は 30 発話である。

| 数 | `pair` | `fast` |
|---|---|---|
| 取り違えた発話（3 repeat のうち 2 以上） | 2（発話 6、28） | 4（発話 6、14、28、29） |
| 向き `ja_as_en` | 0 | 1 |
| 向き `en_as_ja` | 2 | 3 |
| `lang` が ja でも en でもない `final` | 0 | 3（`zh`） |
| 原文の言語と同じ言語の `translation`（settled） | 0 | 0 |
| `asr.lang.fallback`（`step` ごと） | `sv_tag` 3 | 0 |
| `final` が 2 以上の発話 | 12 | 14 |
| `final` の無い repeat | 11 | 14 |
| どの repeat にも `final` が無い発話 | 3、5、27 | 3、5、13、27 |

仮の線は取り違えた発話が 2 以下である。
`pair` の 2 は線の内、`fast` の 4 は線を超える（線の外）。
線の置き直しは設計 10.9.1 の手順で行い、この記録では動かしていない。

`jq` の数え方の対照として、`pair` の `.events.jsonl` の全 `final` の `lang` を ja に書き換えて同じ式で数えると、取り違えた発話が 15（`en_as_ja` 15、`ja_as_en` 0）になった。
manifest の en は 15 発話である。

3 発話目（manifest は ja の短い発話）は、1 repeat 目の `finals` が `pair` と `fast` のどちらも 0 だった。
