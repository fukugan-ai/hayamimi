# IP-2 の実走の記録

IP-2 は、`lat-dialog`（ja と en の交互の 30 発話）を 3 repeat、1 本のマイクから `hayamimi`、中継、訳の server を通して流し、記録が欠けないこと（合否）と、各発話が自分の言語で読まれたか（記録だけ）を見る受入である。
2026-10-23 に、commit `6a98f08` の木で `pair` を 1 本流した。IP-9 の `asr.segment.unread` の数もここに記録する。

## 行ごとの結果

| 行 | 結果 | 理由 |
|---|---|---|
| T-IP-02-001 `ip02_each_dialog_utterance_is_read_in_its_own_language` | 打てなかった | test の `find_llama` は機械の `llama-server` がちょうど 1 つであることを要る。共有の 18081 と、この run の 18084 で 2 つになる。前回の記録と同じ理由で、共有の server は止めていない |
| 設計の合否の文を、手で打った run に当てた結果 | 満たした | 下の表 |

設計 10.9 の IP-2 の合否の文（逐語）：

> `lat-dialog` の run が欠けなく 1 本記録される（`stream.machine.refused` なし）。欠けないとは、`ip02_pair.jsonl` が 90 行（repeat 1〜3 と発話 1〜30 が 1 回ずつ）で、同じ名前の `.events.jsonl`、`.summary.json`、`.machine.jsonl` が在り、`final` が 1 件以上在ることである。

| 項 | `pair` |
|---|---|
| `ip02_pair.jsonl` の行数（期待 90） | 90 |
| repeat と発話の組の数（期待 90） | 90 |
| `.events.jsonl`、`.summary.json`、`.machine.jsonl` | 3 つとも在る |
| `stream.machine.refused`（`stream` の出力と `.machine.jsonl` への `grep -c`） | 0 と 0 |
| `final` の数 | 113 |

数えた手段は `wc`、`jq`、`grep -c` で、test の関数の出力ではない。
`grep -c` の対照として、`stream` が機械の門で断られた run の出力（branch `run/ip2-ip5` の `ip05.md` が書く `cargo test` の形の run）に同じ語を打つと 1 を返した。

## 打った command

訳の server、`hayamimi`、中継、`stream` を、それぞれ `sudo -n nice -n -5 sudo -n -u <本人>` を前に付けて起こした。

```
llama-server -m CAT-Translate-3.3b-Q8_0.gguf --host 127.0.0.1 --port 18084 -ngl 99 -c 16384
hayamimi --input ws --mode pair --source file --models <repo>/models --serve 8833
hayamimi-relay live --events http://127.0.0.1:8833/events --llm http://127.0.0.1:18084 --serve 8835
hayamimi-eval stream --wav testdata/lat-dialog.wav --repeat 3 --relay-port 8835 --own-pid <hayamimi> --own-pid <中継> --own-pid <訳の server> --own-llama-port 18084 --out ip02_pair.jsonl
```

## `asr.segment.unread`（IP-9）

`ip02_pair.log`（`hayamimi` の出力）に `asr.segment.unread` は 2 件だった。

| `start_s` | `end_s` | `reason` | `lang` | `tier` | level |
|---|---|---|---|---|---|
| 201.958 | 202.804 | `empty_decode` | en | omni | info |
| 392.614 | 393.556 | `empty_decode` | en | omni | info |

`reason` ごとの数は `empty_decode` 2、`empty_text` 0 である。
対照として、同じ log の `asr.final.published` は 113 件で、`final` の数 113 と一致した。

3 発話目（manifest は ja の `ピカピカブ` の叫び）は、3 repeat とも `finals` が 0 だった。
`.jsonl` の `finals` が 0 の組は `1-3`、`2-3`、`3-3` の 3 つだけで、どの repeat にも `final` が無い発話は 3 だけである。

3 発話目の `t_start_us` は repeat 2 が 202.087 s、repeat 3 が 392.754 s である。
2 件の `asr.segment.unread` の `start_s` は、それぞれ 0.129 s、0.140 s だけ早い。
repeat 1 の発話 1（`start_sample` 0）の `t_start_us` が 0.108 s なので、`stream` の時計は `hayamimi` の時計より 0.1 s ほど進んでいる。この差を引くと、2 件は repeat 2 と repeat 3 の 3 発話目の中に入る。
repeat 1 の 3 発話目には、対応する `asr.segment.unread` が無い。

したがって、設計 10.9.2 の 6 を窓の中の `asr.segment.unread` の有無で読むと、3 発話目は「区間の無い発話」でなく「読んだが空だった発話」に入る（repeat 2 と 3 に在るため）。
`start_s` と `t_start_us` を引き算せずに比べると 2 件は窓の外になり、「区間の無い発話」になる。どちらで数えるかは設計の文が決めておらず、この記録では決めていない。
repeat 1 では VAD が区間を作らず（設計 10.12 の H43 と同じ形）、repeat 2 と 3 では 0.85 s と 0.94 s の区間が認識器へ渡って空に読まれた。

## 記録だけの数

数え方は設計 10.9.2 で、割り当ては `hayamimi-eval` の `placement_us` と同じ（`final` の `t1_s` を、始まった最新の窓へ）。
test の関数（`record_dialog_run`）が走らなかったので、同じ file を `jq` で数えた（式は run の dir の `count.jq`。repo に入れていない）。

| 数 | `pair` |
|---|---|
| 取り違えた発話（3 repeat のうち 2 以上） | 0 |
| 向き `ja_as_en`、`en_as_ja` | 0、0 |
| `lang` が ja でも en でもない `final` | 0 |
| 原文の言語と同じ言語の `translation`（settled、`of: final`） | 0 |
| `asr.lang.fallback`（`step` ごと） | `sv_tag` 3、そのほか 0 |
| `final` が 2 以上の発話 | 8 |
| `final` の無い repeat | 3 |
| どの repeat にも `final` が無い発話 | 3 |

仮の線は取り違えた発話が 2 以下で、`pair` の 0 は線の内である。
数え方の対照として、全 `final` の `lang` を ja に書き換えて同じ式で数えると、取り違えた発話が 15（`en_as_ja` 15）になった。manifest の en は 15 発話である。
`jq` が割り当てた `final` の数は 113 で、`.jsonl` の `finals` の和（113）と一致した。
