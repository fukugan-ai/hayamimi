# IP-5 の実走の記録

IP-5 は、1 枚の頁に両方の向きの訳が出るかを、`hayamimi`、中継、偽の訳の server、`chrome-headless-shell` を実際に起こして測る受入である。
2026-10-23 に、`lat-dialog` の最初の 4 発話（ja、en、ja、en）で打った。
結果は 4 行とも落ちた。
落ちた理由は、頁の描画より前の段で、`final` が 4 件にならなかったことである。

| 行 | 結果 | 逐語の error |
|---|---|---|
| T-IP-05-001 `ip05_one_page_shows_both_directions` | 落ちた | `the finals are ["ja", "en", "en", "en", "en"], not ja, en, ja, en: IP-5 is not judged` |
| T-IP-05-002 `each_direction_shows_its_arrow_and_the_translation_the_server_made` | 落ちた | `5 rows, not 7` |
| T-IP-05-003 `a_page_without_relay_in_its_address_shows_no_translation` | 落ちた | `5 rows, not 4` |
| T-IP-05-004 `the_relay_publishes_four_settled_translations_for_the_four_lines` | 落ちた | `the settled translations are [("file-1", "en"), ("file-1", "en"), ("file-2", "ja"), ("file-2", "ja"), ("file-3", "ja"), ("file-4", "ja"), ("file-5", "ja")], not [("file-1", "en"), ("file-2", "ja"), ("file-3", "en"), ("file-4", "ja")]` |

## 打った command

wasm の束と 3 つの binary を作った。
`cd native` の下で、`CARGO_TARGET_DIR` を `native/target` にして打った。

```
cargo build --release --target wasm32-unknown-unknown -p hayamimi-ui --features web -j 2
wasm-bindgen --target web --no-typescript --out-dir target/release/ui --out-name hayamimi-ui target/wasm32-unknown-unknown/release/hayamimi-ui.wasm
cargo build --release -p hayamimi-eval -p hayamimi -p hayamimi-relay -j 2
```

test は 3 回打った。

1. `cargo test --release -p hayamimi --test ip05 -j 2 -- --ignored`。4 行とも `hayamimi-eval stream ended with exit status: 2` で落ちた。`stream` が `error: the machine is busy: cargo 1, rustc 0` で起動を断った（`stream.machine.refused`、`reason` は `build`）。数えられた `cargo` は test を起こした親の `cargo test` 自身で、ほかの `cargo` は居なかった。
2. 上の test binary を、`cargo` の親 process なしで直に起こした。`ip05-0f48de7b34a27ff4 --ignored`。結果は上の表の 1 回目。
3. 同じ直の起こし方をもう 1 回。結果は上の表と同じ error 文で、要約行が 2 回目。

## run が見た物

2 回とも同じ `final` を見た（`file-1` から `file-5`）。

manifest の 3 発話目（`start_sample` 180811）は ja で、`final` が 1 件も付かなかった。
4 発話目（en）の `final` は 3 件に割れた。
IP-2 の run の 1 repeat 目でも、3 発話目の `finals` は 0、4 発話目の `finals` は 3 だった（`pair` と `fast` の両方。`ip02.md` を見る）。
`final` が 4 件にならなかった原因は、この記録では特定していない。

1 回目の `hayamimi-eval stream` の `l_asr` は 1 件で 12404 ms だった。
最初の英語の発話で認識器を読む時間を含むかは、確かめていない。
2 回目も `final` の並びは同じだった。
