# hayamimi の要件定義書

正本は英語版の [requirements.md](requirements.md) で、この文書はその日本語版である。食い違ったときは英語版に従う。

散らばっている要件の結論を 1 か所に集め、各行に出所を添える。
ここで新しく決めることはしない。
決め、理由、測り方は出所の文書が持ち、食い違ったときは出所の文書に従う。
実装の進み具合は [status.ja.md](status.ja.md)（正本は [status.md](status.md)）に在る。

出所の略号は次のとおりである。

- **G**：`docs/design/goals.md`
- **D**：`docs/design/rust_port.ja.md`（受入 ID は `RP-<n>`）
- **C**：`docs/design/conversation_subtitles.ja.md`（受入 ID は `CS-<n>` と `CX-<n>`）
- **S**：repo の直下の `state.json` の `goal` と `targets`（git の外に置く作業の記録で、公開の repo には載らない）

## 1. 目的

話してから、訳した字幕が出るまでを、今の Python 版より短くする（D 冒頭、D 1.1）。
日英の会話で、相手の発話を自分の言語の字幕で読めるようにし、会議、動画、配信の上に重ね、相手へも届ける（C 冒頭、S `goal`）。
実行時の経路から Python を外して Rust にし、推論を GPU に載せる。GPU が無ければ CPU で動く（D 冒頭、D 3.11）。

## 2. 利用者の場面

| 場面 | 何が要るか | 出所 |
|---|---|---|
| 日本語話者と英語話者の会議（Zoom、Teams） | 相手の英語を和訳、自分の日本語を英訳して、1 枚の重ね窓に並べる。訳を相手の会議の字幕へ送る | C 冒頭、C 1、S `targets` |
| 動画を見る（YouTube、MPC-HC） | スピーカーから鳴る音声を字幕にして画面に重ねる | C 冒頭、C 3.1 |
| 動画ファイルの字幕 | 同じ directory に `<名>.<言語>.srt` を書き出す | C 1、C 3.13、S `targets` |
| 配信（OBS） | 自分の発話の英訳を、透明な字幕頁として映像に重ねる | C 1、D 3.8 |
| 一人での書き起こし | マイク、loopback、`/ingest`、wav の音声を逐次認識して確定文を出す | G 決定事項、D 3.7 |

## 5. 採らない手段

要件の形を決めた、採らない手段の主な物を並べる。
理由の全文は出所の節に在る。

| 採らない手段 | 理由の要旨 | 出所 |
|---|---|---|
| Python を残して Rust から呼ぶ | 実行時の経路に Python が残り、置き換えにならない | D 4、C 4 |
| クラウドの認識と翻訳の API | 会話の音声と文字を外へ出す | D 4、C 4 |
| CPU の翻訳器（FuguMT、M2M-100）を GPU の言語モデルの代わりに立てる | 訳の質の上限が model にある | D 4、C 4 |
| 要る物が無いときに理由を出して起動を止める | 1 つ欠けただけで字幕が全部止まる | D 4 |
| 黙って CPU や小さい model に落とす | 遅くなった理由も精度が下がった理由も見えない | D 4 |
| T と E の訳を直列に待ってから出す | 訳の遅れが 2 倍になる | D 3.6、C 4 |
| 断片の訳の時刻を主指標に入れる | 原文が短いほど速く見え、`L` が負にもなる | D 4 |
| end-to-end の音声翻訳 model | 日英の両方向を、許諾と Rust の道の両方を満たして動かせる物が無い | D 4 |
| mobile/ を作り直す | 依頼の範囲の外で、wire 形式の互換で足りる | D 4 |
